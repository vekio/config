= config

Typed YAML and JSON configuration files for Go, with reusable commands and
flags available separately for `urfave/cli/v3` applications.

Configuration types implement `Validate() error`. Values are validated after
loading and before writing. Writes are atomic and use private permissions. The
library currently supports Linux.

== Install

[source,shell]
----
go get github.com/vekio/config
----

== Usage

[source,go]
----
type Config struct {
    Address string `yaml:"address"`
}

func (c Config) Validate() error {
    if c.Address == "" {
        return fmt.Errorf("address is required")
    }
    return nil
}

defaults := Config{Address: "127.0.0.1:8080"}
file, err := config.NewYAMLConfigFile(
    "myapp",
    "config.yml",
    config.Default(defaults),
)
if err != nil {
    return err
}

cfg, err := file.LoadOrCreate()
----

Without `Default`, `LoadOrCreate` uses the zero value of the configuration
type when it needs to create the file. As with every write, that value must pass
`Validate`.

Files use `<user-config-dir>/<app-name>/<file-name>`. YAML and JSON formats are
available:

[source,go]
----
config.NewYAMLConfigFile[Config]("myapp", "config.yml")
config.NewJSONConfigFile[Config]("myapp", "config.json")
----

`DefaultDataDir("myapp")` returns the conventional application data directory.

Applications can select another path explicitly with
`file.SetPath("./config.dev.yml")` before loading or writing the configuration.
They can also set `<APPNAME>_CONFIG_FILE`, which is read when the `ConfigFile`
is created. Non-alphanumeric characters in the application name become
underscores, and empty values are ignored.

== CLI

Reusable commands and a global configuration path flag are provided for
`urfave/cli/v3` in a separate module:

[source,shell]
----
go get github.com/vekio/config/urfave
----

[source,go]
----
import "github.com/vekio/config/urfave"

app := &cli.Command{
    Name:     "myapp",
    Flags:    []cli.Flag{urfave.NewConfigFlag(file)},
    Commands: []*cli.Command{urfave.NewConfigCommand(file)},
}
----

The `config` command provides `show`, `path`, `validate`, and `init`.
`config init --force` replaces an existing file.

The global `--config` flag takes precedence over `<APPNAME>_CONFIG_FILE`.

See link:example/load_or_create/main.go[LoadOrCreate example] and
link:urfave/example/main.go[CLI example].

== Example application

The link:urfave/example[items example] has an `App` with `AddItem` and
`ListItems` use cases. Both use the same `ItemRepository` interface. At startup,
the loaded configuration selects `memory` or `localfs`. The CLI uses the
reusable `config` command and global `--config` flag; it loads the application
configuration only for item commands, after CLI flags have been parsed.

From the repository root, create a configuration file and run the example:

[source,shell]
----
go -C urfave run ./example --config ./items.yml config init
go -C urfave run ./example --config ./items.yml item add --name invoice
go -C urfave run ./example --config ./items.yml item list
----

The generated file selects `localfs`, and `data_dir` is where item files are
saved. To use an in-memory repository, edit `urfave/items.yml` and set
`storage: memory`. In that mode, data lasts for one application run. The
configuration path in these commands is relative to the `urfave` module.

`ITEMS_EXAMPLE_CONFIG_FILE` can select the same file without passing the flag.
When both are set, `--config` wins.
